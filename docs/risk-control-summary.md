# BiliBridge 请求风控保护交付总结

日期：2026-11-10（Asia/Shanghai）。基线为本地 `main` 的 `9e9bafd`，所有改动在 `feat/risk-control` 的独立 worktree 完成。

## 这次解决了什么

此前，账号写入已有保护，但读取没有统一间隔与额度；批量采集遇到风控后还会继续获取字幕或下一条视频。现在，实际发送请求前会检查同一数据目录内共享的保护状态。平台要求暂停后，其他工具和已经排队的请求也会被拦住。

保护状态先落盘再发送；进程重启不会清空额度。发送超时仍保留为未决，必须回读核对；本地门禁在发送前拒绝的操作则明确记为未提交，避免形成错误的永久未决记录。原有审批、预览 token 与去重机制保持生效。

## 默认策略

| 请求类别 | 当前行为 |
| --- | --- |
| API 请求 | 同一数据目录跨进程串行；实际发送间隔至少 1.5 秒 |
| 普通读取 | 每账号 600 次/小时、3000 次/天 |
| 登录恢复 | 认证流程显式申请，且仅限扫码生成/轮询、nav、buvid 白名单；独立计算 600 次/小时、3000 次/天，仍遵守发送间隔 |
| 所有账号写入 | 合计 12 次/小时、30 次/天；失败的已发送请求也计数 |
| 评论、动态和草稿发布 | 两次高影响写入之间至少 120 秒；切换工具不能缩短已有冷却 |
| 私信 | 类别间隔 60 秒；与评论/动态交替时采用更严格的间隔 |
| 收藏、点赞、稍后观看、删除、上传 | 最低 3 秒；正常短间隔会等待，失败退避和平台暂停直接拒绝 |
| HTTP 412/429、明确业务风控、API 非 JSON 成功响应 | 全局暂停按 5、10、20、30 分钟递增；平台 Retry-After 更长时优先遵守 |
| 私信 21020 / 21046 | 分别限制私信 5 分钟 / 24 小时，不冻结普通读取 |

小时额度从该窗口第一次请求起计算；日额度按上海时间午夜恢复，二者独立。累计风控次数不会因一次成功请求清零。未提供面向用户的放宽参数开关。以上均为本地保护策略，不是 B站公布或保证的安全阈值。

## Review 后实际修正的问题

1. **批量采集继续撞接口**：遇到风控、额度、人工验证或登录问题立即停止；保留已取得内容，区分当前未完成视频与尚未处理视频。
2. **图片动态会被自己的短间隔挡住**：上传与最终发布分别计数，正常 3 秒间隔自动等待；长冷却仍拒绝，上传失败仍不降级为纯文字。
3. **切换工具缩短冷却**：评论后改发私信仍须遵守前一次更长的冷却。
4. **网络失败被误标未提交**：实际尝试发送后的失败保留不确定性；只有门禁拒绝才标记未提交。
5. **请求后进程退出丢失结果**：发送前记录持久化中断标记；未完成结果落盘就退出时，后续请求等待人工核对与确认。旧锁超过 180 秒才能自动回收，不会直接丢掉中断标记。
6. **登录恢复入口也被锁住**：恢复接口采用独立额度；新登录必须通过 nav 与账号 ID 校验才能保存。验证码确认、重新登录都不能清空平台暂停或正常预算。
7. **错误透传扩大隐私暴露面**：只向 CLI/工具透传恢复时间、范围及剩余额度等白名单信息，不带出任意上游验证载荷。
8. **测试污染真实保护状态**：现有 HTTP 夹具显式隔离单例门禁，直接单独运行也生效；新增接入测试使用真实门禁、临时目录和模拟 HTTP。
9. **恢复例外范围过宽**：普通业务也会读取 nav/buvid，不能仅凭地址获得恢复例外。现仅扫码、登录校验和登录状态查询显式申请恢复权限；普通工具的同地址请求仍受暂停和普通预算约束。

## 使用和恢复

```powershell
node bin/bili.mjs traffic status
# 在网页完成人工验证，或核对中断请求后，再由用户确认执行：
node bin/bili.mjs traffic resume --go
```

`status` 不联网，展示恢复时间、各类额度和人工处理状态。`resume` 只确认人工验证或中断核对，不清空预算、不提前解除平台暂停、不删除发送账本。登录过期必须重新扫码验证；如同时存在中断标记，先确认中断，再处理登录问题。

## 覆盖范围和交付边界

图片、字幕文件和弹幕下载服从共享暂停，但不占 API 读写额度，也没有另设下载频率或字节预算；它们仍受既有单文件大小和调用方媒体预算限制。媒体 HTTP 与 API 使用同一把传输锁。外部 ffmpeg 在启动联网输入前检查全局暂停；已启动的外部流不会被中止，其内部切片请求也不逐个计数或反馈熔断。其他机器或不同数据目录不共享此状态。

风控保护只减少本插件造成的请求压力，不能证明账号不会被平台限制。本轮没有新增工具或设置页，没有重启 DSH，也没有进行真实账号或宿主审批链验收。当前 `main` 未合并本分支，运行中的插件不会自动使用这些修改。
